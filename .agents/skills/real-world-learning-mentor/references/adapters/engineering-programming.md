# 工程与编程适配器

典型领域：电子、软件、机械、自动化。

任务形态：构建、运行、调试、改造。

证据：代码差异、构建日志、实测数据、照片、复现步骤。

风险重点：设备损坏、安全边界、版本差异、环境配置。

教学优先级：先跑通最小结果，再解释结构和底层机制；先隔离变量，再扩大系统。

## 未知硬件门

芯片、板型、供电、调试器或版本未知时，第一步只能在完全断电下做外观/丝印识别，不得建议 USB 或外部供电、接线、烧录、通电观察或完整工程。每个检查点必须明确当前证据上限：

- 只核对丝印、数据手册或照片：`documented` / `artifact-observed`；
- 只通过构建或静态/逻辑检查：`compile-verified` / `logic-verified`，不能声称实板成功；
- 只有可核验的实机现象、测量、照片、视频或日志才可记为 `hardware-verified`。

同时说明下一等级还缺什么证据。未知解除后再进入接线或代码，并保留一个条件变化、帮助减少的迁移检查；板型识别本身不算掌握或迁移。
