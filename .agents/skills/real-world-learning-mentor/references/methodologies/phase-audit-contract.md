# 四阶段方法审查契约

前台只呈现当前学习组合和任务。后台在调研、方案、授课、复盘四阶段静默运行十方法审查，记录修正，不逐项展示。

## 审查矩阵

| 阶段 | 必查问题 | 合格输出 |
|---|---|---|
| 调研 | 是否找到本质、真实用途、来源时效、风险、反例和边界 | 可靠来源、适用条件、冲突状态 |
| 方案 | 是否从真实成果逆推，是否最短可行，是否保留安全与必要思考 | MVC、任务阶梯、证据、失败分支 |
| 授课 | 是否通俗准确、问题不过量、理论不过量、步骤不含糊 | 当前任务、必要概念、检查点 |
| 复盘 | 是否有证据、错误修正、迁移方向和下一步 | 轻量记录和唯一下一动作 |

审查状态只允许：

```text
pass | adjusted | deferred_with_reason
```

记录字段：`reason / action / evidence_ref`。不保存隐性推理过程。

## 硬失败

- 第一性原理变成长篇理论课。
- 奥卡姆剃刀删掉安全、准确性或必要先修。
- 苏格拉底连续抛多个核心问题，却不给行动。
- 对抗审查只给警告墙，没有修正动作。
- 核心任务未验收就倾倒创意清单。
- 费曼类比失真，且没有补准确术语和边界。
- MVP 没有真实成果或证据。
- 逆向拆解假定用户拥有不存在的资源、权限或数据。
- 复盘比学习任务更重。
- 黑白执行隐藏不确定性，或取消必要思考。
- 每轮展示十个方法名称，造成方法论表演。

任一硬失败出现，该单元不通过，必须修正。

## 窄修正规则

- 理论过量：删到当前任务必要层级。
- 过度精简：恢复安全、准确性、先修和停止条件。
- 追问过多：改成一个核心问题加默认路线。
- 创意过量：保留一个最相关迁移场景。
- 类比失真：补准确术语、边界和反例。
- MVP 失真：增加可观察结果和证据。
- 结果偏见：重新确认资源、限制和替代路径。
- 复盘过重：压缩为结果、错误、修正、证据、下一步。
- 执行过黑箱：标出确定、条件成立、未知和需要用户判断处。
