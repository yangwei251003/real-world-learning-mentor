# 示例轨道：摄影入门

主适配器：设计与艺术。辅助适配器：工具与操作。示例方法组合：逆向拆解为主，MVP 和费曼为辅；实际运行必须由当前证据重新推荐。

## 首次进入

先确认一个核心问题：你现在最想拍好的对象是什么？例如人像、美食、产品、风景、日常记录。

若用户没有明确目标，默认从“同一场景拍两张可比较照片”开始。

## MVC

在同一场景中拍两张照片，并能解释哪张更好、为什么、下一次改什么。

最低证据：

- 两张原图或截图；
- 拍摄对象和光线条件；
- 至少一个参数或操作差异；
- 用户自己的选择理由。

## 准备度检查

1. 你用手机还是相机？
2. 今天能拍的真实对象是什么？
3. 室内还是室外，光线是否稳定？
4. 你更在意清晰、好看、氛围还是真实还原？
5. 是否涉及他人肖像、隐私或商业用途？

## 真实行动

15 分钟内完成：

1. 选一个固定对象。
2. 拍第一张：不刻意调整。
3. 拍第二张：只改变一个变量，如靠近窗光、降低角度、去掉杂物或改变构图。
4. 对比两张，选出更接近目标的一张。

## 必要理论

摄影先不是参数游戏，而是控制“观众看哪里、感觉如何”。这次只看一个变量：光线方向、主体位置、背景干净度或拍摄距离。

准确术语按需引入：曝光、焦点、构图、主体、背景、景深、白平衡。

## 提示阶梯

- 诊断问题：照片不好看时，先看主体是否明确、背景是否抢戏、光线是否太乱。
- 概念提示：好的构图通常让观众一眼知道你要拍什么。
- 操作框架：固定对象 -> 改一个变量 -> 对比 -> 说明原因。
- 最小示例：同一杯水，分别在桌面中央和窗边侧光下拍。
- 完整参考：给出构图建议前，先让用户提交两张图或描述差异。

## 错误恢复

常见错误：

- 一次改太多变量，不知道哪项有效；
- 只套滤镜，不处理光线和主体；
- 背景杂物比主体更抢眼；
- 手抖或焦点落错；
- 拍摄他人但未确认隐私和授权。

涉及他人肖像、儿童、证件、住址、车牌或商业使用时，先处理隐私与授权。

## 证据评价

合格证据：

- 两张可比较照片；
- 用户说明改了哪一个变量；
- 用户选出更好的一张并说明原因；
- 下一次计划改一个具体点。

只说“我知道构图了”不能标记为 Applied。能换一个场景复现同样改进，才可能标记为 Transferred。

## 作业与迁移

必做：同一对象再拍一次，只改一个变量，并记录结果。

迁移：把同样方法换到美食、人像、产品或学习笔记拍摄中的一个场景。

## 续学摘要示例

```text
目标：拍出主体更清楚的日常照片。
上次成果：完成两张同场景对比照。
当前掌握：Modified，能通过改变背景干净度改善结果。
卡点/风险：还不能稳定解释光线方向。
当前方法：逆向拆解 + MVP + 费曼。
下一步：固定主体，只改变光线方向再拍两张。
```
