# 示例轨道：STM32 入门

主适配器：工程与编程。辅助适配器：工具与操作。示例方法组合：逆向拆解为主，MVP、对抗审查或费曼为辅；实际运行必须由当前证据重新推荐。

## 首次进入

先确认一个核心问题：你手里的板子和下载方式是什么？例如 STM32F103C8T6、ST-LINK、USB 转串口、Keil 或 STM32CubeIDE。

若用户不确定，第一任务不是写代码，而是拍照/描述板卡、接口和线材，建立安全边界。

## MVC

让一个 LED 按可控节奏亮灭，并能解释：

- 哪个引脚在输出；
- 高低电平如何改变 LED 状态；
- 为什么需要开启时钟或完成初始化；
- 如果灯不亮，先查哪三件事。

## 准备度检查

1. 你的开发板型号和供电方式是什么？
2. LED 是板载还是外接？
3. 你使用 Keil、CubeIDE 还是其他环境？
4. 下载器能否被电脑识别？
5. 如果板子发热或下载异常，第一步停止什么操作？

## 真实行动

15 分钟内完成：

1. 确认板卡、下载器、供电和目标 LED 引脚。
2. 打开一个最小工程或示例工程。
3. 编译一次并保存构建结果。
4. 下载到板子，观察 LED 是否按预期变化。

## 必要理论

GPIO 可以理解为 MCU 控制外部世界的开关。输出高低电平，就是让某个引脚接近电源电压或接近地。初始化的目的，是告诉芯片“这个引脚现在由我当作输出开关来用”。

准确术语：GPIO、输出模式、端口时钟、引脚电平、下载/烧录、复位。

## 提示阶梯

- 诊断问题：灯不亮时，先确认供电、引脚、下载是否成功。
- 概念提示：没有开端口时钟，GPIO 配置可能不会生效。
- 操作框架：打开时钟 -> 配置引脚 -> 循环切换电平 -> 延时。
- 最小示例：只保留一个 LED 的初始化和翻转。
- 完整参考：给出完整工程或完整代码前，要求用户先提交错误现象。

## 错误恢复

常见错误：

- 选错芯片型号；
- 端口或引脚写错；
- 下载器驱动异常；
- LED 接法与高低电平预期相反；
- 没有公共地；
- 外接 LED 无限流电阻。

遇到异常发热、异味、供电短路迹象，立即断电，不继续调代码。

## 证据评价

合格证据：

- 编译日志或截图；
- 下载成功信息；
- LED 亮灭照片/视频或用户清晰描述；
- 一处修改：改变闪烁速度或换一个引脚；
- 一条排错记录。

仅“我看懂了”不能标记为 Applied。

## 作业与迁移

必做：把闪烁间隔改成原来的一半，并解释现象变化。

迁移：把 LED 换成蜂鸣器、继电器模块或另一个 GPIO 输出设备之一。迁移前先确认电压、电流和驱动能力。

## 续学摘要示例

```text
目标：学会 STM32 GPIO 控制。
上次成果：LED 已能闪烁，证据为编译日志和用户视频。
当前掌握：Applied，尚未完成独立排错。
卡点/风险：外接负载需要确认电流。
当前方法：逆向拆解 + MVP + 对抗审查。
下一步：改闪烁间隔并解释为什么变化。
```
