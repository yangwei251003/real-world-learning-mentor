# 需求综合与可追溯矩阵

> 研究日期：2026-08-26（Asia/Shanghai）  
> 状态：V1 实施输入；本文件不替代 [`IMPLEMENTATION_PLAN.md`](../../IMPLEMENTATION_PLAN.md)。  
> 证据范围：用户粘贴的原始任务说明、最终实施计划、当前官方文档与本目录来源账本。

## 结论先行

本项目应交付的不是“跨领域课程大纲生成器”，而是一个可被 Codex 发现的、以真实任务推进能力形成的项目内 Skill。它以真实成果为入口，以必要理论为即时支持，以证据和迁移为完成门槛；十种方法论是可选择的教学策略与后台质量闸门，不能取代这一主线。

产品必须在两个互相制衡的目标之间保持张力：尽量降低开始和执行的负担，同时保留学习者不可替代的预测、解释、修改、诊断或迁移动作。把所有决定与操作都交给 AI 会得到“完成感”，而不是可迁移能力。

|---|---|---:|

## 已确定的实现性判断

1. **Skill 结构可行。** 官方文档将 Skill 定义为包含 `SKILL.md` 与可选脚本、参考资料和资产的目录，并明确支持基于名称/描述的渐进加载（见 `OAI-SKILLS-2026`）。因此采用薄 `SKILL.md`、按需 reference 路由，而不制作巨型提示词。
2. **项目级多 Agent 配置可行。** 官方文档支持 `.codex/agents/*.toml` 和并发上限设置；自定义 Agent 应保持窄职责（见 `OAI-SUBAGENTS-2026`）。因此只将调研、架构、评估、状态完整性、对抗审查拆开，不为简单课堂滥用并发。
3. **平台本地记忆不应成为唯一学习记录。** 官方说明本地记忆异步生成、可能跳过且不一定在会话结束时立即更新（见 `OAI-MEMORIES-2026`）。因此使用项目内事件账本作为可验证的恢复来源；平台记忆只是可选上下文。
4. **“十种方法论”不是十条独立课程流水线。** 它们有重叠，且并非所有主张都有同等研究强度。V1 采用“前台有限组合 + 后台质检”来避免高认知成本和虚假个性化。
5. **真实任务不是危险任务。** 高风险/高成本领域以模拟、公开资料、低风险材料或只读分析替代；实际操作必须先满足资源、安全和停止条件。

## 设计约束的优先顺序

出现冲突时，执行以下顺序：

1. 事实准确、安全、隐私、许可证和能力边界；
2. 用户真实成果与可迁移能力；
3. 可执行性、证据和反馈闭环；
4. 最小认知负担与兴趣引导；
5. 方法组合、扩展场景和表现形式。

这避免了“为了极简而省略安全”“为了项目而强迫危险实操”“为了苏格拉底而阻塞行动”“为了方法论而展示方法论”的常见偏航。
