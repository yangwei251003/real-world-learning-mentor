## 抽象后的通用学习内核

### 1. 能力而非章节是主对象

每条学习轨道以 MVC 描述“在现实约束下能完成、解释、排查什么”。课程节点只是到达 MVC 的路径，不是完成证明。STM32 中“能够让实际器件按预期工作并说明原因”自然翻译为摄影的“在同一场景下有目的地拍出并解释两张对比照片”，或经济学的“用一份可核验的生活案例解释并检验一个供需判断”。

### 2. 证据与声明分离

旧硬件教学容易出现“代码已给出就默认实板成功”的风险。新 Skill 使用验证等级：`planned / documented / compiled_or_simulated / self-reported / independently_verified`。任何领域都应把“我觉得会了”与“我以更少帮助在变化条件下完成了”分开。

### 3. 支架是可退场的，不是永久代劳

STM32 场景中 AI 可先给 CubeMX/HAL 支架，但随后必须让学习者预测、电路/代码修改、看现象、定位故障。通用版同样允许 AI 降低机械门槛，却不允许把核心判断和验证全部自动化。

### 4. 任务应是领域原生的

工程/编程侧重 build、debug、operate；科学侧重 experiment、observe、explain；数据/数学侧重 analyze、model、decide；语言侧重 communicate、perform；人文侧重 interpret、compare、argue；设计侧重 create、critique、iterate。统一的是能力闭环，不是表面模板。

## 新增能力：旧 STM32 机制不足以覆盖的部分

1. **八适配器接口**：将真实任务、证据、风险和评估从电子/代码中解绑。
2. **方法双平面治理**：用户可选择方法组合，但十方法审查在后台完成，避免十项“学习法展示”。
3. **来源新鲜度与许可证账本**：硬件/软件/法规等高变化领域有不同复核周期；上游案例仅供机制借鉴。
4. **跨领域状态模型**：区分通用偏好、主题 track、证据和方法组合；不绑定单一板卡或开发环境。
5. **不确定性表达**：把确定事实、依赖条件、未知项明确分开，既不伪装确定，也不丢给用户模糊选择。

## STM32 仍作为首批示范的正确位置

STM32 不是新 Skill 的父项目，而是工程与编程适配器的一个安全测试轨道。面向 `STM32F103C8` 的事实必须以 ST 官方页面和适用数据手册为准（`ST-F103C8-2026`）：产品页显示其工作电压、存储、调试和外设能力，但它不能确认用户手中第三方开发板的实际连线、Flash 容量或器件真伪。因此首次课必须先确认实物、供电与工具；无实板只能标记文档/逻辑/编译验证，不能宣称硬件运行成功。

## 对新项目的可执行规则

1. 先询问或安全默认真实成果，再决定适配器和 MVC。
2. 第一动作必须能在约 15 分钟内开始，且产生可观察信号。
3. 一轮只安排一个主要任务、1–2 个新概念和一个检查点。
4. 每个完成声明都绑定证据类型和验证等级。
5. 通过 `Modify`、`Diagnose` 或 `Transfer` 之一后，才可说核心能力在形成。
6. 工程类仍需专门安全门；其他领域也保留对应的隐私、健康、法律、财务或物理风险门。
