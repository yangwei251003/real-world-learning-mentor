# 反向排除清单：防止教学与工程走偏

> 研究日期：2026-08-26（Asia/Shanghai）  
> 用途：设计、实施、评测和复盘的对抗审查输入。命中任一“硬拒绝”模式时，必须修正或阻断，而不是用更多文字掩盖问题。

## 教学硬拒绝模式

| 模式 | 为什么失败 | 阻断/修正规则 | 对应验证 |
|---|---|---|---|
| 章节或概念倾倒 | 用户还没行动就被大量抽象信息淹没 | 先定义 MVC 和第一个真实动作；每轮最多 1 任务、1–2 新概念 | 首个行动 ≤15 分钟；输出长度/概念数检查 |
| “项目”万能模板 | 人文、语言、艺术被硬改成伪工程项目 | 选领域适配器；使用 Authentic Task 而非统一项目名 | 多领域盲测必须产出不同证据与任务 |
| 十方法论表演 | 方法名称挤占学习注意力，形成伪个性化 | 前台主 1 + 辅 ≤2；十法只后台审查 | 输出不得逐项展示十法 |
| 第一性原理变理论长课 | 追根究底反而拖延实践 | 只解释当前任务需要的机制和边界 | 单元概念上限、任务前行动检查 |
| 奥卡姆删掉安全/先修 | “极简”把用户带到错误或危险操作 | 可延后非刚需，不能删安全、事实、关键前置 | 安全门与准备度失败用例 |
| 苏格拉底式反问机器人 | 连续提问造成羞耻感和无行动等待 | 每轮最多一个核心问题；未知则提示，再未知就讲清 | 对话行为测试 |
| 费曼类比取代事实 | 类比容易形成错误机制模型 | 类比后回到准确术语、条件和反例 | 类比边界检查 |
| MVP 退化成看视频/读文档 | 没有产出、反馈或证据，不会形成能力 | MVP 必须产生真实可观察结果或可验证中间物 | 证据字段非空；完成门检查 |
| 逆向拆解假定资源存在 | 忽略设备、数据、预算、权限或时间 | 先确认/显式默认资源；无资源给替代轨道 | 资源约束、风险与失败分支测试 |
| 复盘成为更重的作业 | 复盘反而提升拖延和负担 | 只记录结果、错误、修正、证据、下一步 | 复盘长度/工作量与主任务比较 |
| 黑白执行隐藏不确定性 | 步骤看似清晰却建立在未知假设上 | 标明确定/条件/未知；给停止条件和错误分支 | 不确定性表达评测 |
| 教程完成即宣称掌握 | 照抄不能证明独立能力 | 至少要求修改、诊断或迁移之一 | `Applied`/`Transferred` 门测试 |
| 把 AI 代劳当学习 | 用户得到成品却不会解释/改动/排错 | AI 可处理机械准备；用户必须完成最小认知和验证动作 | 支架退场与证据评价 |

## 调研与事实硬拒绝模式

| 模式 | 规则 |
|---|---|
| 只依赖模型记忆教快速变化领域 | 正式路线前查官方/一手资料，并写入版本、访问时间与到期日 |
| 社区观点当唯一事实 | 社区只能发现坑点/工作流；关键事实需官方、标准、原始研究或交叉验证 |
| 无限调研 | 满足核心能力、工具、风险、最小成果、误区和来源边界后开始行动；缺口留为条件说明 |
| 伪精确学习画像 | 不使用“视觉型/听觉型”等固定学习风格标签；只根据当前证据调节支架和方法组合 |
| 来源冲突被强行合并 | 保存冲突、条件和待核验点；在高风险处停止而不是猜测 |
| 把自述证据升级成外部验证 | 明确标 `self-reported`；不宣称实机/现实效果已独立验证 |

## 工程、状态与许可硬拒绝模式

| 模式 | 规则 |
|---|---|
| 巨型 `SKILL.md` | 只保留发现、最小状态和路由；重资料按需加载 |
| 为展示多 Agent 而委派 | 简单课堂不强派；并发只给独立且有明确文件/职责边界的工作 |
| 多 Agent 共同写学习状态 | 主 Agent 是唯一写者；子 Agent 返回只读结构化建议 |
| 依赖本地记忆作为唯一记录 | 平台记忆是异步且可跳过的；项目事件账本才是恢复来源 |
| 状态直接覆写 | 必须使用原子替换、锁、revision、幂等键、前向哈希与可重建事件 |
| 保存整段聊天、密钥或隐私文件 | 只保存结构化摘要、相对引用与哈希；默认拒绝秘密/敏感数据 |
| 把 AGPL/CC 限制内容“参考后改写” | 先判断具体文件许可；默认只用抽象机制和原创表达，不导入内容/代码 |
| 复制旧 STM32 项目再改名 | 新根目录独立实现；旧项目只读机制审计和最终哈希比对 |
| 过早建立网页、云、LMS、账号系统 | V1 明确不做；先证明本地 Skill 课堂闭环有效 |

## 对抗审查问题

每次重大方案、课程节点或状态变更前，至少问：

1. 这一步是否直接提升用户完成、解释、修改、排错或迁移真实任务的概率？
2. 删除它会不会伤害安全、准确、证据或必要前置？若不会，能否删/延后？
3. 用户现在能看到什么现象、提交什么证据、在失败时做什么？
4. 这是否把不确定性、成本、权限或风险悄悄转嫁给用户？
5. 这是否只是“看起来像教学/像多 Agent/像个性化”，而没有可测学习收益？

## 处理等级

- `block`：安全、许可、隐私、虚报验证、状态损坏风险；不继续给行动指令。
- `adjust`：理论过量、任务过大、方法组合冲突、来源不新鲜；缩小并重排后继续。
- `defer_with_reason`：有价值但非当前 MVC 所需的内容；记录原因和再进入条件。

此清单是 V1 的对抗测试来源，必须与测试中的硬失败清单保持一致。
