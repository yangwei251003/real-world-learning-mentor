# 学习科学证据与教学机制采用说明

> 研究日期：2026-08-26（Asia/Shanghai）  
> 使用方式：这是设计证据与限制说明，不是要给学习者展示的教育学教材。  
> 重要：研究支持的是具体机制在特定条件下的价值；它不支持“任一学习法对所有人永远最优”的宣传。

## 设计结论

V1 的核心课堂循环由下列证据较强且可操作的机制支撑：主动提取、分散复习、示例与逐步退场、具体/抽象连接、解释性提问、形成性反馈、条件变化后的迁移验证。真实任务、生活化表达、十种方法论和多 Agent 是把这些机制组织成可执行 Skill 的产品设计；它们必须通过本项目盲测，而不是被包装成已被某篇论文“一次性证明”。

## 证据—设计映射

| 教学决策 | 证据与强度 | 对 V1 的具体规则 | 限制/防误用 |
|---|---|---|---|
| 主动提取而非只重读 | IES/WWC 给出强或中等证据建议；Roediger & Karpicke 的延迟测验研究显示测试可增强长期保持（`LS-WWC-2007`, `LS-ROEDIGER-2006`） | 每单元用 1 个预测、解释或小测检查；状态记录薄弱点 | 不是频繁打断式考试；必须给修正性反馈 |
| 分散复习 | WWC 将间隔学习列为中等证据建议；Dunlosky 等综述将分散练习和练习测试评为高效用（`LS-WWC-2007`, `LS-DUNLOSKY-2013`） | 为关键概念/技能保存到期复习项，在新任务中短回忆 | 间隔算法不应伪精确；V1 不复制或宣称实现 Anki 调度算法 |
| 示例、最小样例与退场 | 认知负荷与示例研究支持新手先学习示例；示例步骤渐隐和自我解释可改善后续解题/迁移（`LS-SWELLER-2019`, `LS-SALDEN-2009`, `LS-RENKL-2004`） | 提示阶梯从诊断到完整参考；掌握后减少已给步骤 | 专家可能出现“示例反转效应”；不能一直提供完整答案 |
| 抽象与具体相连 | WWC 建议连接抽象与具体表征；NASEM 将理解底层原则与多情境使用列为迁移条件（`LS-WWC-2007`, `LS-NASEM-2000`） | 用 Concrete → Abstract → Concrete；每课至少一个条件变化或新情境 | 生活类比只建立直觉，必须补回准确术语、边界和反例 |
| 解释性问题 | WWC 建议深层解释性问题；自我解释研究支持学习者处理示例时说明理由（`LS-WWC-2007`, `LS-CHI-1989`） | 每轮最多一个能推动当前任务的预测/因果/排错问题 | 问题不是目的；不知道时给提示，不能变成“反问机器人” |
| 形成性反馈 | NASEM 强调持续、与教学一致的评估；Hattie & Timperley 讨论反馈要回答目标、当前表现与下一步（`LS-NASEM-2000`, `LS-HATTIE-2007`） | 证据到达后反馈“结果—差距—下一动作”；错误进入薄弱点而非惩罚 | 反馈质量和时机比泛泛表扬更重要；避免只报分数 |
| 迁移是学习结果的一部分 | NASEM 指出迁移取决于初始掌握、底层原则、适用条件与多场景使用（`LS-NASEM-2000`） | `Transferred` 需场景/材料/约束/工具之一变化且帮助减少 | 一次类比题不能证明广泛迁移；记录证据等级和范围 |
| 控制新手认知负担 | 认知负荷综述显示新手面对未支架的复杂问题容易无效耗费工作记忆（`LS-SWELLER-2019`, `LS-VAN-GOG-2010`） | 默认 1 任务、1–2 新概念、一个失败分支；先最小动作 | “少”不等于省略必要先修、安全或准确术语 |

## 十种方法论的证据定位

用户要求的十项方法在产品中以“质量镜头”使用，而非都被宣称为同一证据等级的教育干预。

| 方法 | 在 V1 中的实际功能 | 证据定位与约束 |
|---|---|---|
| 第一性原理 | 找到完成当前任务所需的机制/条件，减少死记 | 与原则抽取、适用条件和迁移目标相容；只下钻到当前 MVC 所需深度 |
| 奥卡姆剃刀 | 删除重复步骤、延后非刚需内容 | 属于工程性约束，不是“删理论”授权；安全、准确和必要先修不可删 |
| 苏格拉底式提问 | 触发预测、因果说明和诊断假设 | 有解释性问题/自我解释支持；每轮最多一个核心问题，答不出即支架 |
| 对抗性审查 | 反查难度、风险、伪证据、过时来源、许可与假设 | 属于质量/安全审查；输出必须含可执行修正，不得形成免责声明墙 |
| 头脑风暴拓维 | 已验收后寻找一个迁移或创新应用 | 作为迁移情境生成策略，需要现有能力基础；不在核心任务前堆创意 |
| 费曼学习法 | 先用可复述的平实语言，再返回精确术语与边界 | 与自我解释、解释性提问相容；类比不能代替技术事实 |
| MVP 最小可行学习 | 把首个真实动作压至可开始、可证据化 | 属于产品/任务设计启发；MVP 必须仍有真实结果，不能是“看一遍” |
| 逆向拆解学习 | 从明确成果倒推能力、条件与任务 | 与真实任务、具体—抽象连接相容；先确认资源、权限、成本和风险 |
| 闭环复盘 | 记录结果、错误、修正、证据和下一步 | 与形成性评估/元认知相容；复盘必须比主任务轻 |
| 灰度认知 + 黑白执行 | 明确确定/条件/未知；给无歧义动作与停止条件 | 属于风险沟通与可用性规则；清晰流程仍须保留学习者的最小判断动作 |

## 为什么不采用“十方法全前台”

1. 学习者的工作记忆有限；把方法名称和选择负担放在每一轮，会占用本应投入真实任务的注意力。
2. 一次用很多方法不等于因果上更有效；方法之间存在重叠，且无证据支持“十种同时展示”优于少量准确支架。
3. 因此系统前台只激活 1 个主方法和最多 2 个辅助方法，后台保存极简审查结论。此为降低负荷与保证可解释性的工程选择，而非对学习风格的标签化。

## 可测试的教学假设

以下是假设，必须由项目内 RED/GREEN/盲测检验，不应预先作为事实宣传：

1. 真实成果先行会比同长度的章节先行输出更快带来可提交的首份证据。
2. 基于错误触发的微课与阶梯提示会比整章重复更少造成信息过载。
3. “更少帮助 + 条件变化”的迁移门能更好地区分照抄完成和可独立应用。
4. 显式来源新鲜度与许可证账本会减少技术领域的过时/不可复用建议。
5. 1 主 + ≤2 辅方法组合会比十方法前台展示更易执行、同样可解释。

评测要同时量化首个可行动作、证据质量、迁移、表达清晰度、风险处理和认知负担；不得仅用用户满意度或“输出看起来完整”作结论。

## 对课堂模板的直接要求

```text
真实结果/现象
→ 一个最小动作
→ 1–2 个必要概念（通俗解释 + 精确边界）
→ 一个预测/解释/修改检查
→ 证据或失败分支
→ 下一动作与轻量复盘
```

准备度小测、作业和复习项服务于主动提取、间隔复习和元认知校准；不是为了制造传统学校式负担。对高风险领域，安全门优先于任何教学节奏。

## 不能从证据推出的结论

- 不能说项目式或问题式学习必然优于所有直接教学。复杂新手任务可能需要先示范和更强支架。
- 不能把“费曼/第一性原理/奥卡姆”当作经过统一临床验证的个人学习风格诊断。
- 不能用一次问答、一次成功或自我报告推断全面掌握。
- 不能将语言、人文、艺术的能力缩减为单选测验；应按适配器设计对应的真实表现证据。
- 不能把认知负荷理论用于删除必要安全提示、基础事实或反馈。
